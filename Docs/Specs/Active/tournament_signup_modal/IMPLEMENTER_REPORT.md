## Implementation summary

The sign-up modal is rebuilt from the four-line summary card (`13480:2479`, 978 × 531) into the full
pre-entry briefing: a cross-promotion banner slot, the existing header and date line, a 260 × 360
card-art thumbnail beside a per-tournament description blurb, a localized RULES block, then the
entry pill / prize row and a BACK · CONFIRM pair. **One prefab, two states** — the banner strip and
the content container's top padding move together in `ApplyBannerState`, so the modal measures
**1411** with a banner and **1167** without, both driven by a `VerticalLayoutGroup` +
`ContentSizeFitter` rather than a written number.

The data half adds three GOLFIN-owned description columns end to end (migration → DTO →
`TournamentDefinition` → mapper → a new `TournamentDescription` ladder beside `TournamentDisplayName`),
six localized `tourn.rules.*` rows, and the Tournaments-panel editor for the two blurbs plus their
override key. `OnConfirm`, `CompleteSignup`, `Register`, `TrySpendAsync`, the RP pre-check, the
`GetMyEntry` short-circuit and the navigation target are byte-for-byte untouched.

## Known FAIL items

1. **Em dash colour (fidelity row 3b).** The node paints the `—` between the date range and the
   countdown in `#C7D6EB`; the built modal renders it `#FFFFFF`. **Cause:** SPEC §5.2 requires
   `_dateLineText`'s existing branch to stay byte-for-byte, and that branch composes one string
   (`$"{dateRange} — {countdown}"`) into one TMP. Colouring the dash means either splitting the
   binding into three text nodes or wrapping it in a `<color>` tag — both are rewrites of a branch
   the spec says not to touch. **Unblocked by:** a one-line amendment permitting
   `<color=#C7D6EB>—</color>` in that string.
2. **Migration not applied; backend `.select()` not extended.** Blocked on Cesar's Supabase step and
   on `playlife/backend` not being checked out in this repo. Client and dashboard degrade cleanly to
   "no blurb" until both land.
3. **Banner assignment round-trip untestable.** Blocked on `game_banners` §9 (§7 explicitly says do
   not block on it). The layout half is proven; the resolver is one method.

## Spec deviations

- **Title font asset (D1b).** SPEC pins `Assets/Fonts/Rubik-VariableFont_wght SDF.asset` because it
  is the one Rubik asset declaring `NotoSansJP` in its fallback table. Built on that asset the title
  rendered visibly under-weight (its default instance is Regular 400 and TMP's faux-bold is
  `boldStyle 0.75`), and **Cesar's instruction was "Bold the Title."** The title therefore uses the
  real `Rubik-SemiBold SDF` face + `FontStyles.Bold`, and I added `NotoSansJP-VariableFont_wght SDF`
  to *that* asset's `fallbackFontAssetTable` — a pure addition of the fallback that was already the
  project-wide one, so nothing else changes behaviour. D1b's requirement (the title's asset declares
  the CJK fallback) still holds, and the no-tofu screenshot is the proof.
- **Rubik Medium 500 → Rubik SemiBold 600** for the blurb and rules body. The project ships no Rubik
  Medium face; SemiBold is the nearest available and matches the render's stroke weight better than
  Regular 400 does.
- **`GOLFIN PRESENTS` gradient** is a 2-stop TMP vertex gradient (`#FFFFFF → #828FA1`). The node has
  a 3-stop with `#D1D6E0` at 40 %; `TMP_ColorGradient` has no mid-stop.
- **Date line is one TMP, not three.** Required by §5.2 ("do not rewrite `Populate`'s existing
  branches"). Visually identical apart from Known FAIL 1.
- **Entry pill interior is opaque `#3A3216`, not `rgba(250,199,77,0.18)`.** Per Cesar's instruction
  to reuse the shipped pill. It is also the correct technique here: the gold rim is a *filled*
  9-slice behind the fill, so a translucent fill lets the rim read through the whole pill (that was
  the bug in the first capture). The composited reference interior samples as `#363E3D`, close to
  the shipped `#3A3216`.
- **Separator geometry.** Figma draws a 2 px stroke on a **zero-height** line, so a naive 2 px
  layout element would push the modal to 1021/1265. Each separator is therefore a 0-height layout
  slot (`SeparatorSlot{n}`) carrying a 2 px child — which reproduces both the pixels and the exact
  1015/1259 container heights.
- **`Panel/Border` deleted.** See Cesar correction #4 — the rim is already in the background sprite.
- **New sprite `S_Common_BGCorner50.png`.** Derived (mirrored) from the existing
  `S_Common_BGCorner50Left.png` rather than authored, at Cesar's instruction to "extend to 4 corners".
- **Info row collapse rule (SPEC §5.1) overridden by Cesar** — the row hid entirely on an empty
  blurb; it now hides only when there is neither art nor blurb. See correction 10.
- **`RulesBody` box widened 396 → 416** so Cesar's 27.5 does not wrap the longest rule. The node's
  396 assumes Rubik Medium; the built face is SemiBold, which is wider at the same em.
- **Two `fontSize` rows hand-edited in the generated `TournamentSignupModal_spec.json`**
  (`DescriptionText`, `RulesBody`: 25 → 27.5) so the lint gate encodes Cesar's decision instead of
  failing on it. Everything else in that file is exactly what `figma_node_to_spec.py` emitted.
- **`playlife/backend` §1/§2 not done here** — separate repository; see Known FAIL 2.
