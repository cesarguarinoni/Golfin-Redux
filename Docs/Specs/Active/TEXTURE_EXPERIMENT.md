# Spec: Realistic Terrain Textures Experiment

**Status:** Active — handoff to Claude Code
**Handoff file:** `Docs/TellCode.md` (pointer block) + this file
**Date:** 2026-04-27

## Goal

Replace the current terrain albedo/normal textures with higher-fidelity CC0 sources to make Lomond CC look less "felty" and more like a real golf course. **Experiment-only** — original `Assets/Courses/Textures_2025(JPG)/`, all production TerrainLayers, all production Materials, and `Hole_01_Geo.unity` must stay untouched.

Cesar will compare the experimental hole side-by-side with the production hole and decide whether to promote the textures into production.

## Non-goals

- No changes to splatmap pipeline
- No changes to any production TerrainLayer asset, Material, mesh, or scene
- No fairway mow-stripe shader work (deferred — keeping baked stripes for now)
- No bunker normals rework
- No mask map regeneration (existing 4×4 A=0 mask maps stay)
- No re-import via UHole Lite (we want bit-identical geometry/heightmap to the production hole — only visuals differ)

## Constraints (verified from codebase)

- TerrainLayers use **separate mask map** for smoothness (`m_SmoothnessSource: 1`, `m_MaskMapTexture` slot) — albedo alpha is not read for smoothness, so JPG albedos are safe.
- Existing albedos are JPG; existing normals are JPG. We match that format.
- Mobile build target → keep textures small.
- Hole_01 scene path: `Assets/Golf/Courses/lomond-country-club/Generated/Hole_01_Geo.unity` (gitignored — generated by HoleGeoImporter).
- Hole_01 production TerrainLayer + Material assets live under: `Assets/Golf/Courses/lomond-country-club/Data/hole-01-flat/` (8 TerrainLayers visible in search — `TerrainLayer_T_Fairway_Light.asset`, `TerrainLayer_T_Fairway_Dark.asset`, etc.).

## Two-step workflow

### Step 1 — Texture generation (Node, outside Unity)

Path: `Tools/TextureExperiment/`

Files:
- `manifest.json` — already written, source map for the script
- `prepare-textures.mjs` — already written
- `package.json` — already written (depends on `sharp ^0.33.5`)

Run:
```
cd Tools/TextureExperiment
npm install
node prepare-textures.mjs
```

Output: `Assets/Courses/Textures_Experimental/` containing 25 texture files + `README.md` + `_Source/` (gitignored raw downloads).

### Step 2 — Experimental Hole_01 clone (C# editor script, inside Unity)

Path: `Assets/Scripts/Editor/CourseImporter/BuildExperimentalHole01.cs`

This script does the heavy lifting. **It runs inside Unity** — not as a Node script — because it needs `AssetDatabase`, scene loading, and Unity object graph traversal.

**Menu:** `GOLFIN > Tools > Build Hole_01 Experimental Clone`

**Behavior:**

1. **Pre-flight checks** (abort with clear error if any fail):
   - `Assets/Courses/Textures_Experimental/` exists and contains all 25 expected texture files. If missing, abort with message "Run Tools/TextureExperiment/prepare-textures.mjs first."
   - Source scene exists at `Assets/Golf/Courses/lomond-country-club/Generated/Hole_01_Geo.unity`. If not, abort with "Hole_01_Geo not found. Open the project, run HoleGeoImporter on hole 01, then retry."
   - Output paths don't already exist (or, if they do, prompt to delete and rebuild).

2. **Create output folders:**
   ```
   Assets/Golf/Courses/lomond-country-club/Generated/Experimental/Hole_01_Experimental_Geo.unity
   Assets/Golf/Courses/lomond-country-club/Data/hole-01-experimental/   <- TerrainLayers + Materials clones live here
   ```

3. **Duplicate the scene file** via `AssetDatabase.CopyAsset` to `Hole_01_Experimental_Geo.unity`.

4. **Open the duplicated scene additively.** Find:
   - The Terrain GameObject + its TerrainData reference
   - All overlay-mesh GameObjects under the hole root with `MeshRenderer` components — these are fairway/green/bunker/tee/cart-path overlays. Identify by material name pattern `MAT_T_*`.

5. **Duplicate the TerrainData asset** (`AssetDatabase.CopyAsset`) to `hole-01-experimental/TerrainData_Hole_01_Experimental.asset`. Repoint the duplicated scene's Terrain component at the duplicate.

6. **For each TerrainLayer referenced by the duplicated TerrainData:**
   a. Identify which production texture it points to (via `m_DiffuseTexture` GUID).
   b. Map to the corresponding experimental texture by filename match (e.g. production `T_Fairway_Light.jpg` → experimental `Textures_Experimental/T_Fairway_Light.jpg`).
   c. Duplicate the TerrainLayer asset to `hole-01-experimental/` with suffix `_Experimental` (e.g. `TerrainLayer_T_Fairway_Light_Experimental.asset`).
   d. Edit the duplicate's `m_DiffuseTexture` and `m_NormalMapTexture` to point at the experimental texture GUIDs.
   e. **Leave the mask map alone** — keep the production 4×4 A=0 mask map reference (it's not visual and we're not regenerating it).
   f. Repoint the duplicated TerrainData's layer slot at the new TerrainLayer.

7. **For each overlay-mesh material** (`MAT_T_*` materials referenced by overlay GameObjects in the scene):
   a. Identify production texture via `_BaseMap` and `_BumpMap` properties.
   b. Map to experimental textures by filename.
   c. Duplicate the material to `hole-01-experimental/` with suffix `_Experimental`.
   d. Edit duplicate's `_BaseMap`, `_MainTex`, and `_BumpMap` GUIDs to point at experimental textures.
   e. Repoint each overlay GameObject's MeshRenderer.sharedMaterials slot at the duplicate.

8. **Do NOT touch:**
   - Skybox, lighting, RenderSettings — share with production
   - Trees (TerrainData carries its own copy now via the duplicate)
   - Cart path mesh geometry (only the material is duplicated)
   - Walk camera (it's at scene level — shared by being part of the scene clone)
   - Ball/physics references
   - `Resources/HoleData/Hole_01/zones.json` and `heightmap.bytes` — unchanged

9. **Save the duplicated scene** and close it.

10. **Write a report** to `Docs/Diagnostics/texture-experiment/HOLE01_CLONE_REPORT.md` with:
    - All assets duplicated (paths)
    - All textures swapped (production → experimental mapping table)
    - Any production texture that had no experimental counterpart (warning, list each)
    - Any TerrainLayer or Material that the script couldn't safely duplicate (warning)

**Validation Cesar will run after:**
- Open `Hole_01_Experimental_Geo.unity` in Unity
- Walk camera through the hole
- Compare visually against `Hole_01_Geo.unity`
- Decision: GO → batch script for remaining 17 holes (separate spec). NO-GO → delete the experimental folders and try a different source set.

## Acceptance criteria

- [ ] `Assets/Courses/Textures_Experimental/` contains all 25 expected texture files at correct resolutions
- [ ] `Hole_01_Experimental_Geo.unity` opens cleanly in Unity, no missing reference warnings
- [ ] No file in `Assets/Courses/Textures_2025(JPG)/` is modified
- [ ] No file in `Assets/Golf/Courses/lomond-country-club/Generated/Hole_01_Geo.unity` is modified (verify via diff)
- [ ] No production TerrainLayer or Material under `Data/hole-01-flat/` (or other production dirs) is modified
- [ ] Walking the experimental scene shows new textures everywhere; walking the production scene shows old textures
- [ ] HOLE01_CLONE_REPORT.md is written and lists all duplications + any warnings
- [ ] Total disk delta under 50 MB

## Iteration budget

- Texture script (Step 1): 1 attempt. Already written; if it fails, debug `sharp` install on Windows or surface to Architect.
- Editor script (Step 2): 2 attempts. The TerrainData / TerrainLayer / Material graph traversal is finicky. If 2 attempts can't produce a clean clone, surface to Architect with the specific failure (likely culprit: a layer or material the script doesn't recognize).

## Hard rules

- Do NOT modify any file under `Assets/Courses/Textures_2025(JPG)/`.
- Do NOT modify the production `Hole_01_Geo.unity` scene file.
- Do NOT modify any production TerrainLayer or Material asset.
- Do NOT modify `Resources/HoleData/Hole_01/`.
- Do NOT touch `HoleGeoImporter.cs` or any other importer code — this is a clone-and-edit task, not a re-import.
- Do NOT regenerate splatmaps or mask maps.
- If a texture under `Textures_Experimental/` doesn't exist for a production texture's slot, log a warning in the report and leave the production reference in place on the duplicated asset (graceful fallback).

## After Claude Code is done

Cesar manually:
1. Opens `Hole_01_Experimental_Geo.unity`
2. Walks the camera through the hole, takes screenshots
3. Opens `Hole_01_Geo.unity`, takes the same screenshots from the same camera angles
4. Side-by-side compare
5. Decision:
   - **GO** → next spec covers batch-cloning the remaining 17 holes + (later) promoting experimental textures to replace production
   - **NO-GO** → delete `Textures_Experimental/`, `hole-01-experimental/`, `Hole_01_Experimental_Geo.unity`, and `HOLE01_CLONE_REPORT.md`. Try a different source set.

## Open questions

- None blocking. Edge case: if Hole_01's TerrainData uses a TerrainLayer that points at a texture not in our experimental set (e.g. some hole-specific custom layer), the script logs a warning and leaves that layer alone. Cesar reviews the report to see if anything was missed.
