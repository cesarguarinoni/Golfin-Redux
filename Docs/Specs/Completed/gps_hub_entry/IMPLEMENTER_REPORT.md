# Implementer Report — `gps_hub_entry`

Iteration 1 · 2026-09-01 · baseline in `HEARTBEAT.log` (`=== iter-1 kickoff baseline ===`, HEAD `d5366b06a`)

## Implementation summary

The Home promo banner gained exactly one in-app destination. `BannerPolicy` now parses a `golfin://`
scheme against an enumerated route table (`golfin://gps` → `ScreenId.GpsHub`, and nothing else), and
`BannerSlotBinder.OpenLink` branches on that before the existing `Application.OpenURL`. The hub itself
is a new `GpsHubScreen.prefab` built at 1:1 Figma geometry from node `14011:32819`, showing live
profile numbers from a new `Golfin.Social.UserService` (`/user/detail`) and the player's own posted
scores from `Golfin.Gps.ScoreHistoryService` (`/score/history?limit=3`). The four action tiles and
four of the five hub nav slots are deliberately inert; the two v2 panels ship in the prefab but
inactive. All 23 spec strings (plus 4 relative-date keys — see § Spec deviations) go through the CSV
and are published as `texts` v22.

**Canonical screenshot:** `screenshots/gps_hub_rounds_populated.png` (1170×2532)
**Scene loaded:** `Assets/Scenes/ShellScene.unity` · **Play mode:** Yes · reached via the REAL Home
promo banner's `onClick`, never a test-only button.

## UI fidelity lint

The two WARNs, both examined and accepted:
- `BackRow/BackButton :: flat-fill` — a deliberately invisible (`alpha 0`) hit area, not a fabricated fill.
- `RecentRoundsPanel :: 9slice-cap-kink` — the heuristic assumes a capsule and compares the 50px corner
  against half the 472px height. The panel is a rounded rectangle with a real r50 corner, so the
  "cap radius 125.8px" it estimates does not exist. Verified visually in the canonical frame.

The linter earned its keep here: its first run FAILed 9 panels for `radius` (I had tuned
`pixelsPerUnitMultiplier` by eyeballing the sprite arc instead of following the project convention
`ppuMult = spriteBorder / targetRadius`) and caught a wrong `AvatarInitial` font size in my own spec.

## Spec deviations

1. **4 extra localization keys** (`GPS_HUB_DATE_TODAY` / `_YESTERDAY` / `_DAYS_AGO` / `_WEEKS_AGO`),
   27 rows instead of 23. SPEC §5 sanctions "a 6-line local one: `today / yesterday / N days ago /
   N weeks ago`" while §6 requires "zero new hardcoded `.text` literals". §6 wins: a Japanese player
   reading "3 days ago" under fully translated copy is the exact bug that rule exists to stop. The
   week cutover is at **14** days, not 7, so `{0} weeks ago` is never rendered singular and a fifth
   key is unnecessary. All 23 spec keys are present and unchanged.
2. **`banner.test.ts` lives at `Tools/admin-dashboard/lib/__tests__/banner.test.ts`**, not
   `lib/banner.test.ts` — every other suite in that project is under `lib/__tests__/` and vitest is
   configured for it.
3. **Round rows are uniform 130px** (the node has 130/128/128). The node's first row is taller only
   because it carries the BEST tag; here any row can, so uniform rows are the data-driven shape.
4. **`(N holes)` instead of `(+N vs par)`** — spec-directed: the `activities` row carries no `par`.
5. **Panels are opaque.** The node's panel fill is `rgba(19,52,83,0.6)`; the reused in-game
   `Next Hole Panel` sprite is the same gradient at full opacity. The spec asks for the frame "in the
   game's own panel language", and reusing the shipped atom beat fabricating a translucent one.
6. **A ninth "GPS icon" was not needed.** SPEC §5 lists 8 icons; the nav bar's Home and Profile
   glyphs come from the cloned `PersistentUI` buttons, so 8 was exactly right. Three additional nav
   *button* sprites were exported because the shipped ring sprites have their glyph baked in and
   there is no bare ring in the project.
7. **`content_version.txt` also moved `balls=6→7`.** That publish is not mine — it was already live
   server-side when `export_content.py` ran. The exporter writes the whole cursor file; the line is
   reported here rather than hand-edited out.
8. **`ScreenManager`'s menu-music rule needed no change.** SPEC §4 asks that `GpsHub` be treated as a
   menu screen; `isMenuScreen` is already a deny-list (`!= Logo && != Loading`), so the hub keeps the
   theme playing with zero edits.
9. **The full EditMode `tests-run` was blocked for ~25 minutes** by a test-runner lock held by a
   request that was not mine (`44d1f240-…`), which had also closed `ShellScene` and left two
   `TEST_SaveDataHost` roots in the open scene. I ran the assemblies by direct NUnit reflection in
   the meantime (290 invoked, 268 pass; **all 22 failures were the same `LogAssert.Expect` →
   "No log scope is available"** harness limitation, none task-related), then re-ran the real
   `tests-run` once the lock cleared: **345 passed, 0 failed**. The scene was reloaded from disk to
   drop the leftovers; `git diff` on it is a clean 113-line insert with 0 deletions.
