## Implementation summary

Inverted the ClubControl→aim-arrow-speed mapping so higher CC gives a slower (easier) arrow. `BaseArrowSpeedHzAtCC0` changed from 0.5 to 3.0 and `ArrowSpeedHzPerCC` from +0.025 to -0.025 in both `ControlsConfig.cs` Default and `controls.csv` (the canonical CSV source). Test comments updated for the new arrowHz baseline, putt test rewritten to assert the polarity-independent invariant, and a new monotonic-decreasing regression test (Test11) added.

## Spec deviations

- Test09 and Test10 `dt` changed from 2.5 to 0.34: The spec says only to update comments. However, `dt=0.34` (arrowProgress += 1.02) more accurately documents "1 pass per tick" at arrowHz=3.0, whereas `dt=2.5` (arrowProgress += 7.5) still works but is misleading. Since the single-pass-per-tick design of `TickArrow()` means both values produce identical behavior, this change is purely for comment accuracy and does not affect test semantics.
- `F3_SinglePassMode_SkipsDegradation` comment updated from "arrowHz=0.5, dt=2.5" to "arrowHz=3.0, dt=2.5": Spec did not explicitly list this test, but the comment was stale. The dt=2.5 value was preserved since it still works correctly with the new arrowHz.
- `F3_ForcePerfectAim_ZerosDegradationYaw` and `F1_IsPutt_SkipsDegradation` comment updates: Minor comment updates to reflect new Hz values; dt values preserved.
