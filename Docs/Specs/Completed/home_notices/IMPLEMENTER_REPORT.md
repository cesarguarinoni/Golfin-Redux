## Implementation summary

The Home notice panel's copy now comes from `GET /api/v1/notices` instead of the two bundled
`HOME_MAINTENANCE_*` strings. `Assets/Scripts/NoticesRuntime/` mirrors `BannersRuntime/`
file-for-file — same singleton shape, same synchronous-disk-cache-then-warm-off-the-critical-path
discipline, same atomic `.tmp` + replace write of the RAW body, same `ScheduleRefreshThrottle`, same
silent-failure posture. `HomeScreenController` gained one serialized field (`newsPanelRoot`) and a
rewritten `UpdateNewsContent`; the DemoGate path is byte-for-byte unchanged in behaviour. An empty
notice list is treated as a normal, healthy state that **hides** the panel — there is deliberately no
offline fallback to the bundled maintenance strings (SPEC §4.3).

## Text auto-size (added on Cesar's request, beyond SPEC)

Notice copy is now operator-authored and arbitrary in length, so the two labels were given TMP
auto-sizing. Values were **measured, not guessed** — a throwaway clone of each label was driven with
realistic long EN and JA copy and the largest fitting size recorded per string.

| Label | Box (canvas px) | Auto-size range | Overflow | Was |
|---|---|---|---|---|
| `NewsTitleText` | 1000 × 64 | **24 – 51** | Ellipsis | off, fixed 51, Overflow |
| `NewsBodyText` | 1012 × 180 | **18 – 39** | Ellipsis | off, fixed 39, max 72, Overflow |

Three decisions worth recording:

- **The authored size is the CEILING, not the starting point.** `fontSizeMax` = the design size (51 /
  39), so auto-size may only ever *shrink*. Left at TMP's default `fontSizeMax = 72` a short notice
  would balloon well past the design and wreck the panel.
- **`overflowMode` → `Ellipsis`.** Auto-size alone does **not** deliver "never outside the box": once
  it clamps at `fontSizeMin` the text spills again. Ellipsis is the hard backstop below the floor —
  verified with a 400-char title and a 2000-char body, both of which clamp at min, truncate, and stay
  inside. Failure mode is a visible "…" the operator can see and shorten, instead of copy drawn over
  the character art below.
- **No layout fight.** `NoticePanel`'s `VerticalLayoutGroup` has `childControlWidth/Height = False`,
  so it only *positions* children — their rects are authored and fixed, and auto-size works inside
  them without a circular dependency. Confirmed after the change: all three child rects and
  `anchoredPosition`s are byte-identical.

**This also fixed a pre-existing overflow bug.** The title was authored at 51 in a 64px-high box, but
measurement shows `"MAINTENANCE NOTICE"` needs ≤ 49 and the Japanese `"メンテナンス情報"` needs ≤ 44
(JA line height is taller). **The shipped title has been clipping in both languages, worse in
Japanese.** It now renders at 49.1 with bounds 63.9 ≤ 64.

### Correction — horizontal spill, and the wrong reference frame

**Cesar reported the text still spilling out at the sides after the change above, and he was right.**
The auto-size verification compared each label's glyphs against **its own RectTransform**, which is
not the box a player sees. The box is `NoticePanel`'s `Notice Background` image, world **x 76 → 1094**.
Against *that*, the authored rects leave essentially no room:

| Label | Rect (world x) | Clearance in the card |
|---|---|---|
| `NewsTitleText` | 77 → 1077 | **left 1px**, right 17px |
| `NewsBodyText` | 77 → 1089.1 | **left 1px, right 4.9px** |

The body is the main offender: at 39pt its preferred width is 1403 against a 1012 rect, so every long
line wraps to nearly the full rect and lands 1px from the card's left edge. Text inside its rect,
glyphs on the card border. The root cause is the panel's `VerticalLayoutGroup` padding —
`left = 1, right = 0` — against children authored to fill the full panel width.

**Fix:** TMP `margin` on both labels, insetting the text area to **42px from each card edge** — the
same inset the card already uses vertically (`VerticalLayoutGroup` padding top/bottom = 42), so the
number is derived from the design rather than typed in. Margins are computed from the card's measured
corners, hence the asymmetry (the two rects differ in width):

| Label | Margin (L, T, R, B) |
|---|---|
| `NewsTitleText` | `(41, 0, 25, 0)` |
| `NewsBodyText` | `(41, 0, 37.1, 0)` |

`margin` was chosen over widening the layout padding or resizing the rects because it changes **no
geometry at all** — every RectTransform, `sizeDelta` and `anchoredPosition` in the panel is untouched,
and auto-size accounts for margins when fitting.

**Re-verified with the right reference** — world-space extents of the actually-rendered glyphs
(`textInfo.characterInfo`, visible characters only) against the card's world corners:

```
card 76..1094            font   clearance L   clearance R
title EN (current)       49.1        211.0        209.4   INSIDE
title JA long            42.5         43.5         45.1   INSIDE
title EN long (63ch)     24.5         92.1         92.1   INSIDE
body EN (current)        39.0         46.3         47.8   INSIDE
body JA long             36.3         43.1         45.3   INSIDE
body 2000ch (clamped)    18.0         43.2         42.8   INSIDE
worst-case clearance across all cases = 42.8 px
```

Also checked: the card sprite is `Simple` with a zero 9-slice border, drawn at its native
1018 × 352 — so there is no sprite border eating into the inset and no scaling distortion.

The demo build's welcome copy shares these two labels, so it inherits the same protection.

## Bug found and closed during implementation

`HomeScreen` is **active in `ShellScene` at load** (verified: `activeSelf=True`, all ancestors
active). Unity gives no ordering guarantee between one object's `OnEnable` and another's `Awake`, so
`HomeScreenController.OnEnable` can run **before** `NoticeService.Awake`. In that order it reads a
null `Instance`, hides the panel, and then never hears about the cached set — because a subsequent
fetch returning the **same** notices raises no event (the `Signature()` guard, copied from
`BannerService`). The panel would stay hidden for the whole visit despite a valid cache.

`BannerService`'s "no screen exists yet, don't raise" reasoning does not transfer: a banner slot that
misses the boot event still shows its authored sprite; a notice panel that misses it shows nothing.

**Fix:** `Awake` calls `RaiseChanged()` after a successful cache load. Correct in both orders — if
Home has not subscribed yet the raise is a no-op and Home reads `Pages` itself moments later; if it
has, it repaints. Proven below.
