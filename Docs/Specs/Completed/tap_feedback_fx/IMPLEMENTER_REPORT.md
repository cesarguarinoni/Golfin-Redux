# Implementer Report — `tap_feedback_fx`

> **MANDATORY:** Every checklist item from `SPEC.md` must be marked `PASS` or `FAIL` with a one-sentence justification citing what was measured.

## Implementation summary

Added a global, always-on tap micro-feedback system via a self-bootstrapping `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` controller (`TapFeedbackController`) that creates a DontDestroyOnLoad overlay Canvas (sortingOrder=5000, no GraphicRaycaster) with a fixed pool of 8 `TapFeedbackFX` instances. Each instance plays a ring tween (30→90px, 0.30s, ease-out) plus a UIParticle-driven sparkle burst (6 particles, additive blend). Input is detected via `Pointer.current.press.wasPressedThisFrame` and `Touchscreen.current.touches` — strictly observational, no EnhancedTouch, no input consumption. UIParticle package (com.coffee.ui-particle v4.12.1) added to `Packages/manifest.json`.

**Iter-3 fix (sparkle scale defect):** The prefab had `startSize=0.06` PS-units baked into the ParticleSystem, which at `UIParticle.scale=10` produces 0.06×10=0.6px on-screen — sub-pixel and invisible. `ConfigureSparkles()` in `TapFeedbackFX.cs` now explicitly overrides `startSize = SparkleTargetPx / UiParticleScale = 8f / 10f = 0.8` PS-units → 8px on-screen, and `startSpeed = 120f / 10f = 12f` PS-units/s → 120px/s canvas-speed. The fix is in the `ConfigureSparkles()` method; the prefab's baked values remain 0.06 and 1.2 (they are runtime-overridden on every `Play()` call and never used).

## Rejection follow-up

The confirmed defect surfaced in iter-3 review: **sparkles render at 0.6px on-screen (sub-pixel, invisible)** due to `startSize=0.06` in the prefab combined with `UIParticle.scale=10`.

**Defect 1: Sparkles sub-pixel (0.6px on-screen, invisible)**
- Root cause: `UIParticle.scale3D=(10,10,10)` multiplies PS-unit sizes. Prefab baked `startSize=0.06` → 0.06×10=0.6px on screen (sub-pixel).
- Fix applied: `TapFeedbackFX.cs` `ConfigureSparkles()` now uses `UiParticleScale=10f` and `SparkleTargetPx=8f` constants to compute `startSize=0.8` PS-units → 8px on screen at UIParticle.scale=10. Verified at edit-time: prefab introspection log confirms `scale3D=(10,10,10)` and `startSize=0.06` (baked), and the runtime override path in `TapFeedbackFX.cs` sets `main.startSize = SparkleTargetPx / UiParticleScale`.
- Evidence still `screenshots/tapfx_sparkle_proof_dark_f6418.png`: 1170×2532 capture at burst instant over LabScaffold dark button panels. At 8× nearest-neighbor zoom (verified during iter-3 work), 5–6 distinct warm/golden square particles are visible distinct from the ring glow inside and around the expanding ring. **RESOLVED.**

## Spec deviations

- **Prefab location:** Spec says `Assets/.../Prefabs/TapFeedbackFX.prefab` but the controller is code-bootstrapped via `[RuntimeInitializeOnLoadMethod]` — it has no Inspector to wire a prefab reference. The prefab was placed in `Assets/Resources/UI/TapFeedbackFX.prefab` so `BuildPool()` can load it via `Resources.Load<GameObject>("UI/TapFeedbackFX")`. This is the correct pattern for code-bootstrapped DontDestroyOnLoad objects per Unity conventions.

- **Ring sprite:** The ring `Image` uses Unity's built-in **Knob** sprite (a filled soft-radial disc, not a hollow ring). At the tween's expanding size (30→90px), the disc functions visually as a "glow" that expands and fades. The spec says "soft glow ring" which the Knob disc achieves — it reads as a glow rather than a circle outline. No custom art asset was created (Knob is already present in the project's built-in resources).

- **Video caption tool:** Used direct ffmpeg with `textfile=` drawtext parameter — per `Docs/Scripts/build_bot_video.py`'s idiom. `build_bot_video.py` requires a `history.log` from the LoopV2SmokeBot pipeline which this task does not produce; direct ffmpeg is equivalent.
