## Verdict on Phase 2

Net positive. Not promotion-ready yet. Specific wins, specific losses, and a clear-eyed view of why pure source substitution is hitting diminishing returns.

### What landed well
- **Bunker sand (ambientCG Ground054 with `MAT_Bunkers` warm cream tint).** Visibly better than the previous flat-white production. Promote outside of the experiment as a standalone change. See "Standalone promotion" below.
- **Fairway base** reads as believable mowed grass with the new normals working.
- **Rough is now actually green.** Grass005 was the right call — the brown-dirt look is gone.
- **Cart path** stays good across both phases — Asphalt012 + production tint are fine.
- **Clone script architecture** works end-to-end. The shared-vs-per-hole material catch is solved. Re-runnable.

### What's still off
1. **Tee gradient border ring uses old material.** Phase 2's clone script caught more shared materials but missed the gradient border ring specifically — likely created inline by `CreateGradientBorderRing` with a hole-specific naming scheme that doesn't match the discovery regex. Needs targeted handling.
2. **Fairway lost its mow stripes.** Production stripes are NOT generated by interval painting on the splatmap (that approach was tried and abandoned). Production gets stripes from a single texture, `T_Fairway_Mix.jpg`, which has stripes baked into the image; splatmap then paints `Mix` everywhere on fairway. Phase 2's `T_Fairway_Mix.jpg` came out of Grass002 (no stripes baked in) so the visual stripes vanish. Two paths forward: (a) bake stripes back into the experimental Mix texture, or (b) move to a stripe shader and stop relying on a baked stripe pattern.
3. **Rough/shader tone clash at boundary.** **Primarily a color problem, not a smoothness one.** The new rough (Grass005) is brighter and more saturated than the fairway-collar texture next to it. When two surfaces with strong color difference meet on adjacent meshes, the boundary always reads as a hard mask edge regardless of shader. Smoothness mismatch is a smaller secondary contributor. The fix is to bring the rough's hue/saturation/brightness closer to the fairway-collar so the color step is smaller; OR to introduce height-based blending so the transition isn't aligned to the geometry edge. (See Plan C — but Plan E source tuning likely fixes it too.)
4. **Greens and tees too dark.** Real bentgrass greens are visibly LIGHTER and slightly yellower-green than fairway/rough. Tees on Korai are brighter than rough. Phase 2's brightness shifts went the wrong direction.
5. **General flatness persists.** Even with normals correctly imported, the scene reads as low-contrast PBR. Probably a combination of: NormalScale=0.4 too conservative, AO/cavity not contributing, and ambient light too flat.

### Hard agronomic facts (sources: Asian Turfgrass Center, Caddie AI)

| Surface | Species | Visual character |
|---|---|---|
| **Greens** | Creeping bentgrass (Penncross/007 typical at Japan courses) | Fine bladed, dense, smooth, slightly **lighter and yellower-green** than fairway. Almost no visible blade structure at viewing distance. Lomond explicitly markets "ベント芝のワングリーン" (bentgrass single greens). |
| **Fairways + Tees** | Korai (Zoysia matrella, 高麗芝) | Wiry, dense, growing-season green is slightly yellow-tinged. Has visible **grain** from mow direction. Tee surfaces are tighter-mowed than fairway; same species. |
| **Rough** | Noshiba (Zoysia japonica, 野芝) | Same family as Korai, coarser leaf, lower density when un-mowed. Color is similar to Korai but slightly bluer-green. |
| **Bunkers** | White silica sand (Japan inland courses) | Whiter than typical US/European bunker sand. Lomond bunkers from photos read white-cream. |

### Implications for our textures
- The visible distinction between green / fairway / tee / rough is mostly about **mowing height, blade density, and mow direction (grain)**, not raw color. They're all zoysia or bentgrass, all in the same green-yellow family.
- **The rough should be DARKER and slightly yellower-green than fairway, not brighter or more saturated.** Phase 2 did the opposite.
- Going from one source per surface (the current model) to **one or two zoysia-family base sources + per-surface shader treatment** is the more realistic long-term direction.

## Why pure source-swapping is now hitting diminishing returns

The Phase 1 → Phase 2 trajectory taught us:

- Each round of "find a better CC0 source" gets us 50–70% of the visible improvement we wanted, but we leave 30–50% on the table because of factors no albedo can fix:
  - **No proper mow stripes** — production's baked-stripe approach (`T_Fairway_Mix`) only works when the source we drop in already has stripes; CC0 grass photos don't, so we need to either bake them in ourselves or move to a shader
  - **No grain anisotropy** (shader effect — Korai grain affects ball roll AND visual highlight direction)
  - **No height-based blending** at material boundaries (a shader feature) — would soften boundary color steps
  - **Mismatched smoothness** between TerrainLayer (uses mask map) and overlay materials (uses scalar `_Smoothness`) — a secondary factor in boundary clash
  - **No subtle wear/divots/cart-traffic patterns** — production-grade courses have these
- The clone script can repoint textures forever; it can't add shader features or bake stripe patterns into source albedos.

**The next big visual jump comes from a mix of better source tuning AND shader work.** Phase 3 should be both, not just one or the other.

## Future experiment plans (in order of expected payoff)

### Plan A — Bring back fairway stripes

Two sub-options. Both restore visible mow stripes on fairways. Pick one, not both.

**Option A.1 — Bake stripes into the experimental Mix texture (cheap path).**
- In `prepare-textures.mjs`, after generating `T_Fairway_Mix.jpg`, post-process it with `sharp` to add alternating brightness bands. Bands run vertically in UV space; production splatmap UV is world-space-aligned with fairway-along axis.
- Band width ~50–100 texels in UV, brightness modulation ±6–8%.
- Production stays splatmap-only; experimental Mix carries the same stripe pattern as production was relying on.
- **Effort:** ~1–2 hours of `sharp` scripting. No shader work, no pipeline changes.
- **Limitation:** Bands run along the texture's UV axis; on curved fairways the band direction is locked to splatmap UV not to actual mow direction. Same limitation production has.

**Option A.2 — Mow stripe shader (proper path).**
- Custom URP Lit subgraph that takes fairway centerline tangent (per-vertex or sampled from a flow map texture) and modulates `_BaseColor` brightness ±8% in alternating bands of N meters width.
- N ≈ 15m ish (tunable; should match real-world mower width).
- Stripes only on fairway material; greens get cross-grain (perpendicular).
- Source albedo can be plain (stripes layered on at runtime), so any CC0 grass photo works.
- **Effort:** ~1 day shader work + ~1 day pipeline integration (fairway material setup + tangent flow map generation in UHole Lite using the same fairway centerline data the pipeline already produces for cart paths).
- **Risk:** Curved fairways need a flow-map texture, not uniform world-space direction. Manageable.

**Recommendation:** A.1 first as a low-cost holdover so the experiment looks complete, then A.2 when shader work begins in earnest.

### Plan B — Grain-aware highlight shader for greens + tees + fairways

**Hypothesis:** Korai grain (and bentgrass grain to a lesser extent) is what makes real golf grass photographs read as "grass" and not "carpet." The grain shows up as anisotropic highlights — light bouncing off blade edges aligned with the mow direction looks brighter than light bouncing perpendicular.

**Approach:**
- Anisotropic specular component on the shader, oriented along the same mow tangent used in Plan A.2.
- Subtle — anisotropy strength ~0.3, not a beauty shader.
- Greens get cross-grain (perpendicular to play direction); fairways get along-grain (toward the green).

**Effort:** Builds on Plan A.2. ~0.5 day if Plan A.2's tangent infrastructure is already in.

### Plan C — Height-based texture blending at boundaries

**Hypothesis:** The fringe→fairway, fairway→rough, and rough→OOB boundaries currently transition through alpha gradients on the splatmap. Real grass boundaries transition through height — short grass and long grass interlock at the boundary, with taller blades visible above shorter ones at the rough edge. Height blending also disguises color mismatches between adjacent textures.

**Approach:**
- TerrainLayer mask maps gain a real height channel (not the current 4×4 A=0 placeholder).
- Custom URP Terrain shader that uses height-based blending between layers (similar to URP's built-in "Blend Tessellation" but for non-tessellated terrain) so the higher-height layer wins at any given splat weight.
- Generate the height channel during UHole Lite splatmap export.
- Side benefit: helps with the rough/fairway color clash flagged above by softening the transition.

**Effort:** ~2 days. Higher risk because Unity's terrain shader is moderately fiddly to override on URP.

### Plan D — Distance-based texture detail fade + tiling break

**Hypothesis:** Texture tiling at distance creates the obvious repeated-pattern look ("plastic" vibe). The fix is to fade detail at distance and add a low-frequency macro-variation texture overlay.

**Approach:**
- All terrain layers gain a macro-variation texture (single channel, low frequency, ~200m world-space tiling) that modulates `_BaseColor` brightness by ±5–10%.
- Detail fades to flat color past 100m.
- Standard mobile-AAA technique, well-documented.

**Effort:** ~0.5 day. Builds on the existing material structure.

### Plan E — Targeted source-research pass with photo reference

**Hypothesis:** Phase 2's source picks were guesses. With Lomond reference photos in hand, we can pick sources with hue/saturation/brightness that actually match the real course — including making rough darker than fairway (which Phase 2 got backwards).

**Action:**
- Cesar gathers Lomond reference photos first (see "Real-world reference" above).
- Architect samples representative pixels from photos to establish target HSV values per surface.
- Cross-reference against ambientCG / Poly Haven / Quixel Megascans for sources that match those target values.
- Apply hue/saturation post-processing in `prepare-textures.mjs` to nudge sources closer to targets where needed.
- Specific deltas Phase 2 needs to fix on this pass:
  - **Rough:** darker, slightly more yellow-green, less saturated — reduce visual contrast against fairway-collar
  - **Greens:** lighter, slightly yellower-green
  - **Tees:** brighter than rough, slightly different hue from fairway
  - **Semi-rough:** between fairway and rough in brightness; phase 2 had it inverted

**Effort:** ~0.5 day source research + ~0.5 day post-processing tweaks + a Phase 3 clone script run.

**This plan can move ahead of A/B/C if Cesar wants another pure-texture iteration before committing to shader work.** The agronomic understanding now in this doc is enough to make a directionally better source pick than Phase 2.

## Recommended ordering

If we ever revisit terrain visuals:

1. **Standalone bunker promotion.** Quick win, zero risk.
2. **Reference photo collection.** 30min of Cesar's time, anchors all future decisions.
3. **Plan E (targeted source pass with photo reference).** Fixes the rough-too-bright / greens-too-dark / semi-rough-inverted issues with no shader work. Probably gets us to "good enough to ship" on visuals.
4. **Plan A.1 (bake stripes into experimental Mix).** Cheap holdover for stripes if we're keeping the splatmap approach.
5. **Plan D (macro variation + distance fade).** Low effort, kills the "plastic" look.
6. **Plan A.2 (mow stripe shader).** Proper stripe solution. Bigger effort, replaces A.1.
7. **Plan B (grain highlights).** Cheap addition once Plan A.2's tangent exists.
8. **Plan C (height blending).** Highest effort. Largely subsumed by Plan E if E is done well, but still the right answer for boundary transitions on the long term.

## Open questions to resolve before any of this re-starts

- **Are mow stripes wanted at all?** Some realistic courses don't have visible stripes (low-mow-frequency varieties). Cesar's call. Production has stripes today via the baked-Mix approach, so default is yes.
- **One green or two?** Lomond uses "ワングリーン" (one-green system) per their Instagram — so we don't need to model the two-green system. Simplifies the experiment.
- **Mobile budget for shader complexity.** Plans A.2+B+D add maybe 2–4 ALU instructions per fragment to the existing URP Lit terrain — well within mobile budget. Plan C is heavier; verify before committing.
- **Korai winter dormancy.** Real Lomond goes golden-brown in winter. Do we want to simulate seasons? (Probably no, but worth flagging — simulating winter would be a Plan F if we ever get nostalgic.)
